# Token foundation

This is the repository law for the default token foundation. The contract and
the default theme change in lockstep: each declares the same token names for a
group, and validation rejects a name missing from either side. The tables below
are the default theme's authored values.

These rules are binding for every family the rebuild has reached. A family
listed in `specs/legacy-families.json` predates this foundation and is exempt
until it is rebuilt in the order `docs/process/build-order.md` sets; that list only
shrinks, and nothing may be added to it.

## Layers

Every token belongs to exactly one layer, and the layer says what may reference
it: a token composes its value from its own layer or a shallower one, never a
deeper one. `validateTheme` (`packages/theme/src/validate.ts`) rejects a theme that
breaks the direction, so the layering is a checked fact rather than a naming
convention.

| Layer       | Holds                                                          | Tokens |
| ----------- | -------------------------------------------------------------- | ------ |
| `primitive` | A value with no meaning attached: a step on a scale.           | 131    |
| `semantic`  | What a value is for: a surface, a border, a control, a target. | 151    |
| `component` | One family adjusting a semantic value for itself.              | 28     |

A token is a **scale root** when it states a value rather than composing one: a
primitive, a colour a scheme paints, or the geometry a density defines. Every
other token must reference another token. A root that restates a literal is
what the three layers exist to prevent — a component deciding, on its own, what
`4px` means.

A non-root token may still state a literal when the contract records why, in
its `literal` field. There are four such tokens, each carrying its reason. Two
describe the absence of a value a scale could hold — no tracking, and a line
box that is the control's own height. The third, `--slotted-font-family-heading`,
holds a typeface that neither primitive face names. The fourth,
`--slotted-material-backdrop`, holds a filter function, which no token names.
An earlier one described the absence of elevation until
`--slotted-control-shadow` was given one.

The component layer holds two scales, and holds each for the reason the layer
exists: a family met a value a semantic token cannot be retuned to give. Button
emptied the layer by reading `--slotted-control-*` directly instead of aliasing
it, which is what lets a theme retune every control once; Avatar refilled it,
because control geometry names a control and an avatar is not one. The bar for
adding to this layer is the one Avatar cleared, written out under **Avatar
size** below: a family may not alias a semantic token here, and it may not
restate a scale that already exists. **File kind** cleared it a second time, for
a palette rather than for a size, and **Code scope** a third, for a palette of
text.

Every token varies on one axis: `base` is stated once, `scheme` is restated by
each colour scheme, and `density` by each density. The axis decides which CSS
block emits the token; the layer decides who may read it.

Every colour token a scheme restates is derived by `recipes.standard` from
six seeds — `accent`, `neutral`, `success`, `info`, `warning`, `danger` —
rather than authored as a literal. `info` is the one tone the reference
predates: it takes the accent's rules on its own seed, so an application whose
accent shares a hue with `success` keeps a neutral-informative intent apart
from both. `packages/theme/src/recipes/standard.ts` is generated by
`scripts/calibrate-standard-recipe.mjs` from
`packages/themes/src/default/reference.json`, the colours the default theme
held before the recipe existed, and from the script's own rules for the
`neutral` seed: the share of its chroma and its hue every neutral token keeps,
and the `GROUNDS` table.

What each group of tokens is for is stated once, in `groups` of
`packages/theme/src/contract.json`; the published `tokens.md` of each binding
is generated from it.

`4xl` was added for `stat-card`, and it is the first step above the size of a

it. Its line height continues the series the scale already runs — tighter as
the type grows — because a figure is one line and needs no room for a second.
`typography` does not read the step yet; it takes it when it is next opened.

## Font family

| Token                           | Default value                                                           |
| ------------------------------- | ----------------------------------------------------------------------- |
| `--slotted-font-family-sans`    | `'Geist Variable', ui-sans-serif, system-ui, sans-serif`                |
| `--slotted-font-family-mono`    | `'Geist Mono Variable', ui-monospace, SFMono-Regular, Menlo, monospace` |
| `--slotted-font-family-heading` | `var(--slotted-font-family-sans)`                                       |

`--slotted-font-family-heading` is the face of every heading and title: the
heading of `typography`, the title of a surface or a region, and the headings
of `prose`. It is a semantic token that names the sans face rather than a stack,
so a theme that substitutes the sans face moves its headings with it. A theme
that sets headings in a face of their own states the stack on this token, and
the contract's `literal` field records why `defineTheme` accepts it.
`packages/styles/src/heading-face.test.mjs` lists each rule that reads it, and
the title parts that keep the face of the text around them.

The sans and mono values name a family no package ships. Nothing in the repository emits
`@font-face` or a font file: `tools/storybook-workbench` installs
`@fontsource-variable/geist` and `@fontsource-variable/geist-mono` for the two
Storybooks, and an application that loads the theme loads the faces the same
way. Where the faces are absent, each stack resolves to its generic keyword.

Substituting the typeface is a declaration of these tokens. The theme emits
them inside `@layer slotted.theme`, and an unlayered rule outranks a layered one
whatever the selectors are:

```css
:root {
  --slotted-font-family-sans: 'X Variable', ui-sans-serif, system-ui, sans-serif;
  --slotted-font-family-mono: 'X Mono Variable', ui-monospace, monospace;
  --slotted-font-family-heading: 'Y Serif', ui-serif, serif;
}
```

Every family reads one of the three, directly, through
`--slotted-control-font-family`, or through a
`--slotted-<family>-title-font-family` hook. No sheet in `packages/styles`
names a family literally, so the three are the whole substitution surface.

reached.

## Glyph

A family draws a component-owned icon with the `Glyph` element —
`<Icon><Glyph name="x" /></Icon>` in React,
`<span slIcon><svg slGlyph name="x"></svg></span>` in Angular — a real `<svg>`
whose paths `scripts/generate-icon-glyphs.mjs` writes into
`packages/core/src/glyph/glyphs.ts` from the same manifest as the tokens below.
The binding renders the element; no stylesheet paints an icon, through a mask,
a pseudo-element or a family hook, and `packages/styles/src/glyph-element.test.mjs`
refuses every family outside its shrinking `PENDING` list that does.

Each token value is a data URI generated by `scripts/generate-icon-glyphs.mjs` from
the Lucide icon that `packages/themes/src/default/glyphs.json` names for the
token, at the `lucide` version pinned in the root `package.json`, which is the
version `lucide-react` is pinned to. The generator runs in the theme's build,
and `packages/themes/test/foundation-doc.test.mjs` fails when a value in
`values.json` is not the drawing Lucide ships. The artwork is painted black, and
the black becomes the mask's alpha when it is used with `mask-image`.

`Paint` is how the geometry is painted: `stroke <width>` is Lucide's own
rendering with round caps and joins, at width 2 unless the manifest says
otherwise; `fill` is the same geometry painted solid, with no stroke.

A component-owned icon is the `Glyph` element; a character is never an icon, and
a glyph token painted from CSS survives only in the families `PENDING` still
lists.

`--slotted-icon-chevrons-right` is one mark rather than two chevrons a family
draws twice: the distance between the two strokes is part of the artwork, and a
family compositing two masks would decide it again, differently, each time. It
was added for `pagination`, whose first and last triggers are the one pair in
the library that means "all the way to the end" rather than "one step"; like
every chevron it is mirrored by the family that draws it, so the same token
serves both ends of the row.

`--slotted-icon-panel-open` and `--slotted-icon-panel-close` are the two states
of the control that shows and hides an application's navigation region, and
they were added for `app-shell`. They are one artwork with the chevron turned,
for the reason `eye` and `eye-off` are one artwork with a stroke added: the
control reads as the same control changed rather than as two marks swapping
places.

The mark draws the region it toggles — a frame with a bar down one side —
which is what neither of the two marks the field reaches for does. Three bars
say _a menu is here_ and say nothing about which menu or where it goes; the
scale does not hold them and this is the argument for not adding them. A double
chevron says _all the way to the end_, which is what `pagination` uses it for,
and a single chevron says _a list opens here_, which is what `select` uses it
for: both were tried on this control and both are a promise the control does
not keep. The panel is the one mark that names the thing being moved, and it is
the mark Linear, Vercel and shadcn all draw on the same control.

It is direction-sensitive, so the family drawing it turns it: a navigation
region at the inline end, and a right-to-left document, both mirror the whole
artwork, bar and chevron together.

`--slotted-icon-arrow-left`, `--slotted-icon-pin` and `--slotted-icon-pin-off`
were added for `page-header`. The arrow is the mark on the control that takes
the reader back to where they came from — the one glyph in the scale that
points along the reading direction, so the family that draws it mirrors it in a
right-to-left document. The pin and the struck pin are the two states of the
control that holds the header area open while the page scrolls: one artwork
with a stroke added, for the reason `eye` and `eye-off` are, so the pressed
control reads as the same control changed rather than as another icon.

`--slotted-icon-copy` is two sheets, one behind the other, rather than a pair of
brackets or a page: the mark has to be read at sixteen pixels beside a value, and
the overlap is what says _duplicate_ at that size. It was added for
`description-list`, whose long values are reachable by copying rather than by
truncation, and `code-block` in wave 7 needs the same mark.

`--slotted-icon-calendar` is the mark on a date picker's trigger, and it is the
one glyph in the scale that names a _kind of value_ rather than an action or a
status. It was added for `date-picker`, whose trigger had been drawing the
chevron `select` uses — which says "a list opens here" and is the wrong promise:
what opens is a month, and a reader who has learnt the chevron from every other
control on the form learns the wrong thing from it. All seven implementations
surveyed for that family draw a calendar there, and none of them draws a
chevron. `date-range-picker` in wave 8 takes the same mark.

`--slotted-icon-clock` is the same argument for the other half of the chain, and
it was added for `time-picker`. What opens behind that trigger is a list, so the
chevron `select` uses would not be a wrong promise here the way it is on a date
picker — it would be a _silent_ one: a form holding a name, a date and a time
would show a calendar on one control and the same chevron on the other two, and
the mark would have stopped naming anything. All eight implementations surveyed
for `time-picker` draw a clock. `datetime-picker` in wave 8 draws both marks,
one per surface, and takes no third glyph.

The last six were added for `upload`, and they are the first glyphs in the scale
that name a _transfer_ rather than a value, a status or a piece of text. Each one
is a mark the family draws on a control the reader presses, and none of the marks
already in the scale stands in for any of them.

`--slotted-icon-upload` is the mark on the drop region, and it is the one every
surveyed implementation of that region draws. `--slotted-icon-file` is the
preview a row falls back to when there is no thumbnail to show; a sheet of paper
is not `copy`'s two sheets, which mean _duplicate_, and not `inbox`'s tray, which
means _received_.

`--slotted-icon-file` and the eight marks beside it are one set:
the same page, with a different mark inside it. They say what a file is at
thirty-two pixels, where the name is truncated and the extension is three
characters — a reader picking one attachment out of nine reads the silhouette
before the words. Eight kinds cover what an upload actually meets, and `--slotted-icon-file` is
what everything else falls back to. A PDF and a word-processed document are two
kinds rather than one, because they are the pair a reader most often has to tell
apart and the world has already given them different colours: `file-text` is the
page of lines a PDF is, and `file-type` the page of set type a document is.
Slides take `presentation` — the one mark in the set that is not a page, and the
one mark anybody recognises for a deck.

The marks carry no colour of their own. The colour is the tile they are knocked
out of, and that is a scale of its own: see **File kind** below.

The four control marks are one set and are chosen against each other, because
they appear together on one row. `--slotted-icon-play` sends a file that is
waiting and resumes one that is paused; `--slotted-icon-pause` suspends it;
`--slotted-icon-rotate-ccw` sends it again after a failure; and
`--slotted-icon-trash` takes it out of the list. The fifth control on that row —
cancel — draws `--slotted-icon-x`, which the scale already held: stopping a
transfer and removing a file are two different actions and the row has to say
which is which, so a cross that means _stop this_ stands beside a bin that means
_take it away_. Reusing the cross for both was the alternative, and it makes the
two controls one control drawn twice.

`--slotted-icon-text-wrap` is the mark on the control that wraps a block of
source, and it was added for `code-block`. It is a return arrow under two
lines — the one mark a reader has learnt for "wrap" from every editor — and
nothing in the scale stands in for it: `chevron-down` says a list opens, and
the arrows say where the reader goes. Docusaurus draws the same mark on the
same control.

`--slotted-icon-bell` is the mark on the control that opens an application's
notifications, and it was added for `top-navigation`. Carbon and UI5 both draw
a bell there, and nothing in the scale stands in for it: `inbox` says
_received_, and a dot on a mark says _something is here_ without saying what.
It is the second glyph, after `calendar` and `clock`, that names a kind of
thing rather than an action — what waits behind the control is a list of
notifications, and the reader has learnt the bell for it from every product
they use.

`--slotted-icon-trending-up` is the mark beside a delta, and it was added for
`stat-card`. It is one artwork for two directions: Lucide's `trending-down` is
`trending-up` reflected across the horizontal axis, stroke for stroke, so the
family draws the one glyph and turns it — `scaleY(-1)` — for a fall, the way
every chevron in the scale is mirrored by the family that draws it rather than
held twice. A flat delta draws `--slotted-icon-minus`, which the scale already
held. The mark is a line with a rise in it rather than an arrow, because an
arrow beside a number says _go there_ — `arrow-left` takes the reader back,
`external` takes them out — and this one says _it went this way_. shadcn's
dashboard draws the same pair on the same badge.

`--slotted-icon-image-off` is the mark a picture leaves behind when it does
not arrive, and it was added for `image`. The scale had `file-image`, which
says _a file of this kind_ — it is the tile `upload` draws beside a name — and
a broken thumbnail in a product grid is not a file, it is a hole where a
photograph should be. Ant Design and Chakra v2 both paint a placeholder there;
Lucide's `image-off` is the one drawing that says _a picture, and not here_,
which is the same construction `eye-off` and `cloud-off` already use in this
scale. It is drawn once, on the fallback part, after `fallbackSrc` has had its
turn.

`--slotted-icon-check-check` is two ticks, the mark a message carries once it
has reached the other side, and it was added for `message`. `check` alone says
_sent_; the pair says _delivered_ and, painted in the accent with the word
beside it, _read_ — the convention WhatsApp, Telegram and Messenger taught the
reader. Drawing `check` twice from the family would decide the overlap of the
two strokes again, differently, which is the argument `chevrons-right` already
made.

`--slotted-icon-person` is the only glyph drawn as a filled silhouette rather
than as strokes, because it is the only one that stands in for a photograph
rather than annotating text. It is the last step of Avatar's fallback order,
reached when there is no picture and no name to take initials from.

The six glyphs from `--slotted-icon-circle` onward are the status set, and they
are the only ones that carry their own container. The bare marks above them —
`check`, `minus`, `plus`, `x`, `copy`, `eye`, `eye-off` — are drawn inside a box
some control already provides: a checkbox, a tag's remove button, a description
list's copy button, a text field's reveal button, a number field's stepper.
`minus` and `plus` are one pair drawn
on one grid — the same bar, with a second crossing it — so a split stepper's two
halves read as one control and not as two marks of different weights. `plus` was
added for `number-field`; the scale had held the half of the pair that a
checkbox's indeterminate mark needed and not the other. `eye` and `eye-off` are one pair rather than two marks, because they
are the same artwork with a stroke added: the two states of a password toggle
then read as one control changing rather than as two icons swapping places. A status icon has no such box, so the circle
and the triangle are part of the artwork rather than a stylistic preference,
and the triangle is the one silhouette that has to be recognised before its
colour is. The set is consumed by `status-indicator`, and by `alert` and
`inline-message`, all three of which are required to say what they mean by icon
as well as by tone.

The last four are the marks that carry a whole region rather than annotate a
line, and they were added for `result-state`, whose `status` axis has seven
values and only three marks that already existed. Each one is a silhouette
nothing in the set above can stand in for: a lock is not an alert, a struck
cloud is not a question, a tray is not a dot, and a magnifier is not in the
scale at all. Without them five of the seven statuses would draw the same
circle, which is the reading the axis exists to pass — WCAG 2.2 SC 1.4.1, and
`forced-colors`, where every tone ground becomes one system colour and the shape
is all that is left. They carry their own container for the reason the status
set does: a result state gives its mark no box.

## Target size

| Token                          | Default value |
| ------------------------------ | ------------- |
| `--slotted-target-min`         | `24px`        |
| `--slotted-target-comfortable` | `44px`        |

`--slotted-target-min` is the WCAG 2.2 minimum of 24 × 24 CSS pixels. Theme
validation rejects a density whose control height falls below it, so no density
can be added that makes a control unhittable.

`--slotted-target-comfortable` is the size a control grows to under
`@media (pointer: coarse)`. The theme emits that block itself, per density, as
`max(<density height>, var(--slotted-target-comfortable))`: a dense table keeps
its type and spacing on touch while its controls stay operable, and a theme
whose control is already larger is left alone.

A target smaller than the minimum in one axis — an icon-only control, a remove
button inside a tag — is corrected by the family, either by expanding the hit
area or by spacing the targets apart. Neither is something the theme can do on
the family's behalf.

## Selection geometry

This scale varies by the family's `size` step and by nothing else: the
control glyph scale shrinks with density, and a box that followed it fell to
twelve pixels at `dense`, below the size a mark can be drawn in. The touch
target is not the box either; it is a transparent square of
`--slotted-target-min` around it.

The halo has no size token. It reaches half the gap between the control and
its label, `--slotted-control-label-gap-<step>` divided by two, so it follows
density through the gap and never paints under the label. A stated 32px diameter
reached past the gap in seven of the nine size-and-density pairs.

`--slotted-border-strong` is the line between two surfaces, and it holds the
3:1 ratio a non-text element needs against every surface a control can be
placed on. `--slotted-control-border-color` is the edge of a control at rest,
and it does not: it reads 1.6:1 in `light` and 1.8:1 in `dark`. The edge at
3:1 — `#8190a2`, `#6a6a73` — made every field and outline button the darkest
line on the page and read as a high-contrast scheme in both. A control is
identified by its fill, `--slotted-control-shadow`, its label and its size,
which is the case WCAG 1.4.11 exempts from the boundary ratio; the states that
carry meaning keep it — the focus ring, the invalid edge and the checked fill
are measured at 3:1 elsewhere in this document. `--slotted-disabled-border`
stays a step lighter than the control edge in each scheme, so an unavailable
control still reads as less than an available one.

`--slotted-border-subtle` is the rule inside a surface: a divider, the edge of
a shell region, the seam under a header. It reads 1.30:1 in `light` and 1.37:1
in `dark`, a step above the 1.2:1 it had, which was one step too quiet next to
the edge of a control.

`--slotted-control-surface` is the ground a control carries at rest, and it is
`--slotted-surface` in every scheme: a field stands on the same plane a card
stands on, and what separates the two is the canvas under them. It is a token
of its own rather than a second name for the surface so that a theme can move
the field without moving the card, and so that `forced-colors` can map it to
`Field`, the system's own control ground — the only token in the foundation
mapped to it. When the field became a token, `--slotted-surface-sunken` in
`light` moved from `#fbfbfb` to `#f8f8f8`: at two per cent from white, the
canvas gave a white field nothing to stand on, which is the same fact
`app-shell` records as the reason `inset` exists. Both grounds now follow the
`neutral` seed; on the default seed the field is `#f8fafe` and the sunken
canvas `#f1f5fb`. The step is 1.05:1 against the canvas in `light` and 1.06:1
in `dark` — small, because a field is a place to type and not a card.

`--slotted-state-hover`, `--slotted-state-pressed` and `--slotted-state-selected`
are layers laid over the surface an element stands on: the scheme's text
colour at a share over transparency, so one token reads the same on
`--slotted-surface` and on `--slotted-surface-raised`. The shares rise from
hover to selected to pressed. Under forced colours each layer is `Canvas`, and
the family carries the state with `Highlight` and an outline.

`--slotted-surface-material` is the ground of a bar that floats over scrolling
content — a phone tab bar, a sticky banner — drawn as a material: the surface
at a share over transparency, with `backdrop-filter:
var(--slotted-material-backdrop)` behind it. The filter varies by scheme: a
light page holds less contrast, and under a 72 per cent surface a 20 pixel blur
left a flat grey there, so `light` blurs 6 pixels and `dark` 20.
`high-contrast` keeps the surface opaque and the filter `none`. Under
`prefers-reduced-transparency: reduce` the theme sets the surface to
`var(--slotted-surface)` and the backdrop to `none`, from the contract's
`reducedTransparency` field; under forced colours they are `Canvas` and
`none`.

`--slotted-current-edge` is the edge of the row the reader is on — the
destination `side-navigation` and `top-navigation` mark `aria-current` — and it
is drawn as an inset shadow over the tone ground that carries the state. It is
`transparent` in `light` and `dark`, where the accent ground and the accent ink
say where the reader is and a grey line around a tinted row read as a chosen
option; it is black in `high-contrast`, where every tone ground is the page's
own white and the edge is all that is left to say it. Under forced colours it
maps to `Highlight`, the ground those rows are painted with there.

`--slotted-focus-ring-color-invalid` is the ring a control in error draws, and
it is the only state that changes the ring's colour. A family points
`--slotted-focus-ring-color` at it under `[data-invalid]` rather than repainting
each rule that draws focus. Under forced colours it maps to `Highlight` like
the ring it replaces, because a focus indicator is a focus indicator before it
is an error.

`--slotted-control-invalid-edge-width` is the edge an invalid control adds
inside its border, drawn as an inset shadow in the invalid border colour at
rest and under focus; the default theme sets it to
`--slotted-border-width-thin`, so an invalid edge reads two pixels against one.
It is what tells an invalid control from a valid one where colour cannot: in
`high-contrast` the control edge, `--slotted-tone-danger-border` and both rings
are the same black (WCAG 1.4.1). Every family that draws an invalid edge reads
it, most through a family token such as
`--slotted-text-field-invalid-edge-width`; `checkbox` and `radio-group` add it
to the width of their border, which forced colours keep, and a frame whose edge
is a shadow restates it under forced colours as an outline. The families that
state invalid without an edge, `wizard`'s colour-only progress segments among
them, are listed in `packages/styles/src/invalid-edge.test.mjs`.

The six tones — `accent`, `secondary`, `neutral`, `success`, `warning` and
`danger` — each carry the same nine roles: `solid`, `solid-hover`,
`solid-active`, `on-solid`, `surface`, `subtle-hover`, `subtle-active`,
`border` and `text`. Their values are not tabled here because the set is one
hundred and sixty-two entries; the contract holds every name and the contrast
test holds every ratio. `neutral` is ink: its solid steps are aliases of
`--slotted-surface-inverse` and its two steps, its label is
`--slotted-text-inverse` on the fill and `--slotted-text` without one, and its
tinted roles are `secondary`'s.

A tone's `surface` role is a ground and not a separator. It is bracketed from
both sides: far enough below the page to be seen, and far enough above the
tone's own `text` to be read. On a light page the two brackets do not overlap.
A ground at 1.5:1 under white sits at L ≤ 0.650, while `accent-text` needs
L ≥ 0.655 to hold 4.5:1 over it — and `danger` needs 0.680, `success` 0.892,
and every tone in `high-contrast` needs 0.671 to 0.756 against a 7:1 floor
(G9). The
`high-contrast` scheme closes the question outright: it paints every tone
ground the page's own white, so no ground in that scheme separates from
anything.

So a state that has to be seen is carried by a pair, and the ratio is measured
across the pair rather than on the ground alone. The chosen row, card, option
and toggle draw `--slotted-tone-accent-border` at the non-text ratio against
the page _and_ against the ground it encloses — 5.17 | 7.31 | 21.00 and
4.24 | 6.78 | 21.00 in the default theme — and `--slotted-tone-accent-surface`
tints what that edge encloses, at 1.22 | 1.08 | 1.00. This replaces the
threshold B6 asked for between a pressed toggle's ground and an unpressed
one's, which no set of hexadecimals can reach.
`packages/theme/conformance/theme-conformance.mjs` holds the pair.

Where a state has no edge to pair with, the ground is not recalibrated either;
it is mixed from the tone's `text` role at a fraction of opacity, which is the
one role every scheme keeps legible over the surface. `--slotted-selection-halo-opacity`
does this for the pointer halo (CK7) and `--slotted-highlight-tint-opacity`
for the band behind a matched span (CB10).

The five tones cannot give it, for the reason they could not give **File
kind**: a tone means something — `danger` is a failure — and a series means
nothing but itself. A chart of eight regions painted from the tones would say
that the fourth region had failed, and a sparkline of the error rate painted
`danger` would say the same thing about every error rate, rising or falling.
The slot says which series; the tone, where a family carries one, says how the
series is doing.

The ladder is derived from the `accent` seed, so a theme with a new accent
gets a first series of its own hue and seven that stand around it, where a
fixed blue first series clashed with any other accent. Slot 1 takes the
seed's hue; slots 2 to 8 step back 45° at a time. Odd and even slots stand at
two lightness steps — 0.42 and 0.6 in `light`, 0.82 and 0.6 in `dark`, 0.3 and
0.5 in `high-contrast` — because at one lightness a reader without red or
green cones tells apart two hues on the red-green axis by nothing, and the
slots beside each other in a stack or a legend have to differ by more than
hue. The chroma asks for 0.14 to 0.15 and is capped where sRGB stops holding
it at that lightness and hue (`fitGamut`, a Fourier series in the hue fitted
toward the inside), so a slot is painted as derived on any screen. For every
accent hue, 15° apart, neighbouring slots clear ΔE 8 in OKLab under simulated
deuteranopia and protanopia, and every slot clears 3:1 against
`--slotted-surface`, `--slotted-surface-raised` and `--slotted-surface-sunken`
in `light` and `dark` and 4.5:1 in `high-contrast` for every seed of the grid
(`packages/theme/src/recipes/standard.test.ts`).
`packages/themes/test/default-theme.test.mjs` measures the default theme's.
A theme still sets any slot by hand through `schemes`.

`--slotted-data-{slot}-on` is the ink drawn on a slot used as a ground — an
icon on a category tile. It is the neutral seed's light or dark ink, whichever
reads further from the slot's step at its worst hue, and every pair clears
3:1 (WCAG 1.4.11) for every seed of the grid in every scheme. White on a light
`dark` slot, which an application reached for with no ink of its own, fell to
2.93:1.

What the scale does not hold is a neutral and a sequence. A series that is
there for comparison rather than identity — last period behind this one —
is drawn in `--slotted-text-muted`, the step the page already uses for an
aside; a reference line is `--slotted-border-strong`, the line between two
surfaces at 3:1. A sequential ramp is `chart`'s to open, because no consumer
of this wave reads one. Under forced colours the whole scale is `CanvasText`:
one series, and identity is then said by shape, texture or label, which is
`chart`'s decision to make.

The three lifted steps are two layers each, the upper one offset by at least
its own blur less its negative spread: a shadow with no spread bleeds as far
sideways as it falls, and a panel with a twelve-pixel blur read as a halo
round the panel rather than a floor beneath it. The negative spread pulls the
shadow's box inside the panel's sides, so what shows there is the last of the
blur, and what falls below is the shadow. Tailwind, Radix Themes and Primer
build every floating shadow this way. The edge stays the panel's border.

`--slotted-control-shadow` is the shadow a framed control carries at rest, and
it is the same geometry as `--slotted-shadow-xs` at the same ink in `light`
because, with the control edge under 3:1, the shadow is what separates a
control from its ground rather than a second line under the edge. At `0.04`
over one pixel it was not visible. It varies by scheme for the reason every
other shadow does — the ink of a shadow is not the same value in a light scheme
and a dark one — and it is `none` in `high-contrast`, where a control already
carries a black edge and a second one would only thicken it.

scale: the initials' type size, the glyph, the square corner radius, and the
overlap in a group. A proportion of a box is geometry, and geometry is not a
token.

## Rules for component tokens and containers

1. A component token's value is another token, unless the contract records the
   reason for the literal. The universally exempt values are `0`, `none`,
   `auto`, `100%`, `transparent`, `currentColor`, and `inherit`.
2. Durations and easings come from the motion scale. Infinite animations must
   stop or disable under reduced motion; shortening is insufficient.
3. A component-owned icon is the `Glyph` element, a real `<svg>` the binding
   renders inside the `icon` box; never a mask, a pseudo-element or a
   character.
4. A container breakpoint cannot be a token because
   `@container (min-width: var(--x))` is invalid. A reflowing family declares
   `container-type: inline-size` and its own `container-name`; its breakpoints
   are literal. A page-surface family — `app-shell`, `detail-panel`, `page`,
   `page-header` — composes by size class, and a size class is the width band
   of its container: compact below `600px`, medium from `600px` to `1023px`,
   expanded from `1024px`. Its width conditions use only `600px` and `1024px`,
   which script reads as `COMPACT_BELOW` and `EXPANDED_FROM` from
   `@slotted/core/measure`; `packages/styles/src/size-classes.test.mjs` rejects
   any other threshold in the four families. A family that reflows its own
   content (`card`, `list-item`, `alert`) keeps thresholds of its own, because
   they answer to that content and not to the page. `top-navigation` folds its
   `low` items at `1024px` and its `high` items at `480px` for its own content;
   its `medium` step is the app-shell's overlay step, `600px`.
5. A family is selected in public by `data-ui` and its parts by `data-part`. A
   class name is not contract, and `packages/styles/src/identity.test.mjs`
   rejects a stylesheet that keys on one.
6. A weaker state holds itself back for every stronger one, in the order
   `STATE_PRECEDENCE` declares. `packages/styles/src/states.test.mjs` rejects a
   hover or active rule that does not.
7. `overflow-clip-margin` takes no token arithmetic, and does not contain what
   hangs out of a box. Measured in Chrome 150.0.7871.181:
   `CSS.supports('overflow-clip-margin: calc(8px)')` is `false` — any `calc()`
   is refused at parse time, and a `calc()` reached through a `var()` is not
   refused but computes to `0px`, because a `var()` is substituted after the
   property has been validated. A bare `var()` and a literal both compute. And
   with either, a pseudo-element hanging eight pixels past a sixteen-pixel box
   still reports 24 against a client width of 16: a clip margin widens the
   region that is painted, never the region that scrolls. A family that needs a
   halo or a hit area outside its control anchors it so it does not hang —
   which is what `checkbox` and `radio-group` do, and what
   `checkbox.styles.test.mjs` and `radio-group.styles.test.mjs` hold by
   rejecting the property outright.

## Current boundary

The foundation changes four rendered values on purpose.
`--slotted-text-muted` in the light scheme darkened to meet 4.5:1 against the
sunken surface, and `--slotted-border-strong` in both schemes darkened to meet
3:1 against the surface it separates. `--slotted-control-shadow` left `none`
for the shadow tabled above, so a framed control is separated from its ground
by something other than its own edge. `--slotted-focus-ring-color` in the dark
scheme left the light grey `#d4d4d8` for `#75a0fc`, the accent border step,
which makes the ring the same idea in both schemes instead of a neutral in one
of them.
The three lifted shadow steps left their single symmetric blur for the two
layers tabled above, so a floating panel shades its floor and not its sides.

The dark scheme's `--slotted-tone-secondary-subtle-hover` left `#18181b` for
`#212225`. It had been calibrated on `--slotted-surface` alone, and on
`--slotted-surface-raised`, where every menu, popup list and sheet is drawn, it
stood 0.005 above the ground in OKLab lightness, so a highlighted item read as
unlit. It now stands at least 0.025 above every surface and 0.021 short of the
pressed step, and `theme-conformance` holds a 0.02 step on every surface.

The light scheme's `--slotted-tone-success-text` left `#15803d` for `#007633`,
0.033 in OKLab and the one colour `recipes.standard` moves past the 0.02
`packages/themes/test/reproduction.test.mjs` allows. The recipe derives the
tone text from the `success` seed and caps its lightness with a ceiling fitted
over every seed of the same hue and chroma, so that the text holds 4.5:1 on its
own tone surface for all of them and not only for the default seed. On the
default seed the ceiling sits below the seed's own lightness, 0.527, and takes
the text to 0.494: 5.25:1 on `#dcfce7` where it read 4.57:1.

The dark scheme's `--slotted-tone-accent-border` and `--slotted-tone-accent-text`
left `#60a5fa` and `#93c5fd` for `#75a0fc` and `#a2c0ff`, 0.025 and 0.022 in
OKLab, and the focus ring, which aliases the border, moved with them. The
recipe turned both 10° and 13° from the seed's hue, the drift of the palette
the default theme was matched to; every other seed took that turn toward blue,
and a violet accent at 283° drew a periwinkle edge. Both now keep the seed's
hue, and the floor bounds alone lift them to the contrast the scheme needs.

The neutral grounds left their achromatic values for a tint of the `neutral`
seed. Fitted to the achromatic values they had, `--slotted-surface`,
`--slotted-surface-raised` and `--slotted-surface-sunken` in `light`, and
`--slotted-surface-raised` and `--slotted-surface-inverse` in `dark`, kept none
of the seed's chroma, so a neutral seed recoloured lines and text while every
card, popover, dialog, menu and page kept its colour. Each ground now keeps 0.22
of the seed's chroma, capped at the chroma sRGB holds at its lightness for
every hue: 0.006 for the light grounds and the dark inverse, 0.012 for the
light sunken ground, 0.03 for the dark surface and raised grounds, 0.025 for
the dark sunken one. sRGB holds no chroma at lightness 1, so the light surface
and raised grounds moved from 1 to 0.985, the light sunken ground from 0.979 to
0.97, where the lowest data slot on the default seeds, `--slotted-data-4`,
reads 3.47:1 on it and every slot reads at least 3:1 for every seed of the
grid, and the light
`--slotted-tone-secondary-subtle-hover` from 0.968 to 0.959, 0.011 below the
sunken ground as before. On the default seed the largest move of a ground is
0.016 in OKLab: the light page, card and field are `#f8fafe` where they were
`#ffffff`. `high-contrast` keeps white grounds and achromatic lines and inks —
its disabled border and foreground are `#595959`, its hover and active fills a
grey, not black: every tone ground of that scheme is the page's own white, and
`--slotted-text-muted` is the one neutral token there that carries the seed.

Every other token of the `neutral` seed then followed it the same way. The fit
to the slate reference gave each line, highlight and ink a fixed share of the
seed and the hue offset slate has: in `light`, `--slotted-text` turned 8° from
the seed and `--slotted-border-strong` 6°. In `dark`, every highlight, fill and
line kept 0.135 to 0.219 of the seed's chroma under grounds that keep 0.22,
and `--slotted-text` kept none. A highlight with less chroma than its ground is
a step toward the opposite hue: on a pink seed, the hover of a
`side-navigation` row read green. Each neutral token of `light` and `dark` now
takes the seed's hue with no offset and at least 0.22 of its chroma. Its
chroma is capped at 0.06 and at the chroma sRGB holds at its lightness for
every hue: 0.019 for the light highlight, 0.033 for the light fills, 0.035 for
the light text, 0.006 for the dark inks. `--slotted-text-muted` in
`high-contrast` keeps its share under the same gamut cap, 0.047. On the default
seed the largest move is 0.007 in OKLab, the light `--slotted-text` from
`#0f172a` to `#0d1828`, and no ratio this document cites moves.

The light `--slotted-scrim` left the slate tint `rgb(15 23 42 / 0.45)` for the
achromatic `rgb(0 0 0 / 0.41)`, like `dark` and `high-contrast`: a tinted page
under the old scrim read two colours at once, its own and the scrim's slate.
0.41 is the alpha a black veil needs to match the old tint's darkening of a
white page: `rgb(15 23 42 / 0.45)` over `#ffffff` composites to `#93979f`, sRGB
relative luminance 0.307, and `rgb(0 0 0 / α)` over `#ffffff` reaches that same
luminance at α ≈ 0.410.

`--slotted-code-comment` in `light` and `dark` left its own literal,
`#5b6b7f` and `#a1a1aa`, for `var(--slotted-text-muted)`: the prose already
named it the muted text step, and a literal that only approximated that token
would miss it on the next retune of `text-muted`. The move on the default seed
is 0.0014 OKLab in `light` (`#5b6b7f` → `#5c6b7f`) and 0.0075 in `dark`
(`#a1a1aa` → `#9da3aa`). `high-contrast` keeps its own literal, `#1f2937`,
unchanged.

Everything else the theme emitted before this foundation resolves to the same
value, which `packages/themes/test/resolve.test.mjs` holds. A row leaves that
table when its token leaves the contract, or when a change like the ones above
is taken deliberately and written here.

Consumption is the rebuild's work: the families listed in
`specs/legacy-families.json` do not yet read these scales, and each one starts
doing so when it is rebuilt.
