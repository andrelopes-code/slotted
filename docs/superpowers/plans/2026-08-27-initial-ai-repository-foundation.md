# Initial AI Repository Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create the minimal reproducible repository, agent contract, validation workflow, and public GitHub project required to begin Slotted development without implementing product code.

**Architecture:** The repository is a pnpm workspace with Turborepo coordinating ordinary package scripts. Root configuration remains explicit and centralized while small; React and Angular are represented only by non-publishable directory anchors. Local and CI checks are deterministic, read-only, browser-free, and proportional to the changed surface.

**Tech Stack:** Node.js 24 LTS, pnpm 11.24.0, Turborepo 2.10.12, TypeScript 6.0.3, ESLint 10.9.1, typescript-eslint 8.68.0, Prettier 3.9.6, GitHub Actions, GitHub CLI.

---

## File Map

The implementation creates or tracks these files:

- `.node-version`: single Node.js major consumed locally and by CI.
- `package.json`: workspace metadata, exact tool versions, and stable root commands.
- `pnpm-lock.yaml`: reproducible dependency graph generated by pnpm.
- `pnpm-workspace.yaml`: future package discovery under `packages/*`.
- `turbo.json`: task graph for future package-level `verify` scripts.
- `tsconfig.base.json`: strict shared TypeScript defaults without choosing a framework build target.
- `eslint.config.js`: root flat ESLint configuration for JavaScript and TypeScript.
- `prettier.config.js`: formatting policy.
- `.prettierignore`: generated and dependency paths excluded from formatting.
- `.editorconfig`: editor-independent whitespace defaults.
- `.gitignore`: local, generated, cache, coverage, and build artifacts.
- `AGENTS.md`: concise normative operating contract for coding agents.
- `CONTRIBUTING.md`: contributor setup and command selection.
- `README.md`: public project purpose, experimental status, and quick start.
- `LICENSE`: MIT license owned by Slotted contributors.
- `PROJECT-PRD.md`: existing product context, tracked without modification.
- `packages/react/README.md`: non-publishable React package anchor.
- `packages/angular/README.md`: non-publishable Angular package anchor.
- `docs/decisions/README.md`: policy for adding decisions only when needed.
- `.github/workflows/ci.yml`: one read-only validation workflow.

- [ ] **Step 2: Add the repository-specific agent contract**

Create `AGENTS.md`:

```markdown
# Slotted Repository Instructions

## Scope

`PROJECT-PRD.md` is product context, not an automatic backlog. Implement only the requested task and preserve unrelated user work.

React and Angular must remain idiomatic to their frameworks. Share specifications and contracts when useful; do not force shared implementation without demonstrated need.

## Working Loop

1. Read only the context required for the task.
2. Define or infer a bounded, observable outcome.
3. Change the smallest coherent set of files.
4. Select verification from the changed surface and risk.
5. Resolve related failures and report concrete evidence.

Do not impose a hard time limit on implementation. When work becomes long or changes phase, report the result obtained, available evidence, current obstacle, and next materially different attempt. Reassess or split work when attempts repeat without new evidence.

## Verification

- Isolated documentation or configuration: run its specific checker.
- One task-bearing package: run that package's filtered checks.
- Shared contract or dependency edge: run affected packages and dependents.
- Toolchain, release, or cross-cutting change: run `pnpm check:full`.
- Security-sensitive or otherwise high-risk behavior: add independent review.

Use `pnpm check` for the normal fast gate, `pnpm check:affected` for changed packages and dependents, and `pnpm check:full` only when the change surface warrants it.

Except for `pnpm format`, verification commands must not modify files.

## Browser Automation

Do not use Playwright for exploratory browsing, generic UI inspection, broad screenshot collection, or open-ended visual review. Browser automation is allowed only for a named deterministic scenario with explicit assertions and clear failure semantics.

## Restraint

Do not add dependencies, abstractions, packages, planning artifacts, reviewers, or subagents by default. Introduce them only when current scope or risk justifies them.

Do not run every available check merely for reassurance. Completion means the requested result is present, relevant checks pass, and remaining limitations are explicit.
```

- [ ] **Step 2: Add the read-only CI workflow**

Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches:
      - main
  pull_request:

permissions:
  contents: read

concurrency:
  group: ci-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  validate:
    name: Validate
    runs-on: ubuntu-latest
    steps:
      - name: Check out repository
        uses: actions/checkout@v4

      - name: Install pnpm
        uses: pnpm/action-setup@v4

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version-file: .node-version
          cache: pnpm

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Validate repository
        run: pnpm check:full
```

Do not add browser steps, a version matrix, publishing permissions, automatic fixes, remote Turbo credentials, or an explicit job timeout.
