Deploying a service⁠#

A deployment is three decisions: where the code runs, when it moves, and who is told. Read the prerequisites first, and the CLI reference⁠ (opens in a new tab)⁠ when a flag is unclear. The old blue-green flow is gone.

Prerequisites⁠#

  • An account with deploy permission on the target project.
  • The command line tool, installed with npm i -g @acme/cli.
    • Version 4 or later.
    • Authenticated once.
  1. Build the image.
  2. Push it to the registry.

A deployment that cannot be reversed is a migration, and it needs a different review.

import { deploy } from '@acme/cli';await deploy({ env: 'production', wait: true });

It resolves once every instance reports healthy.

Before the first deployment:

Note

Deployments run in the order they were queued.

Tip

Pass --wait to block until every instance is healthy.

Important

Production needs a second approver.

Warning

A deployment during a migration waits for the migration to finish.

It is not cancelled.

Caution

Rolling back deletes the instances the deployment created.
